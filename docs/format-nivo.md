# ساختار پشتیبان نیوو (`.nivo`)

## رمزگذاری
فایل `.nivo` یک دیتابیس SQLite است که با **AES-128-ECB** و padding از نوع **PKCS7** رمز شده است. کلید یک رشته‌ی ۱۶ بایتی ثابت داخل
خود برنامه است (برای همه‌ی کاربران یکی است)؛ بنابراین رمزگشایی یعنی فقط خواندن فایل خودتان، نه شکستن رمز.

نشانه‌ی ECB: بلوک‌های تکراری ۱۶ بایتی در فایل رمزشده (بخش‌های خالی دیتابیس همه صفرند و همیشه یک بلوک رمز یکسان می‌دهند).
بعد از رمزگشایی ۱۵ بایت اول `SQLite format 3` است.

```bash
nivo2parmis decrypt my.nivo -o my.sqlite   # با DB Browser for SQLite باز می‌شود
```

## جدول‌های مهم

| جدول | کاربرد |
|---|---|
| `AccTransaction` | تراکنش‌ها (قلب داده) |
| `Account` | دسته‌ها (درآمد/هزینه) — با `ParentAccountId` دو سطح |
| `Bank` | بانک‌های تعریف‌شده |
| `Wallet` | کیف پول (معمولاً یک عدد) و `CurrencyTypeId` |
| `Project` | پروژه‌ها (برچسب تراکنش) |
| `Contact`, `Budget`, `Loan`, `Saving`, `Cheque`, `RecurringAccTransaction` … | بخش‌های دیگر برنامه (این ابزار منتقل نمی‌کند) |

## ستون‌های مهم `AccTransaction`

| ستون | معنی |
|---|---|
| `AccountId` / `AccountName` | دسته. نام ذخیره‌شده در تراکنش ممکن است با نام فعلی دسته فرق کند (تغییر نام)؛ ابزار از جدول `Account` می‌خواند |
| `AccountGroupId` | ۱ = درآمد، ۲ = هزینه |
| `Amount` | **علامت‌دار**: درآمد مثبت، هزینه منفی (واحد: ارز کیف پول؛ معمولاً تومان) |
| `RegFaDate` | تاریخ شمسی `YYYY/MM/DD` (مرجع اصلی تاریخ) |
| `RegGeDate` | زمان میلادی به میلی‌ثانیه (UTC). ساعت ثبت از آن به‌دست می‌آید؛ روز آن همیشه با `RegFaDate` (به وقت تهران) می‌خواند |
| `BankId` | خالی = پرداخت نقدی؛ پر = از آن بانک |
| `MasterAccTransactionId` | دو تراکنش یک انتقال («جیب به جیب») با این ستون به هم وصل‌اند (متقابل) |
| `ProjectId` | پروژه |
| `Note` | یادداشت |
| `Tag`, `GeneralReferenceId` | متادیتای تراکنش‌های واردشده از پیامک بانک (JSON) |

## دسته‌های از پیش‌تعریف‌شده (`Account.PredefinedType`)

درآمد: `101` قرض گرفتن، `102` پس گرفتن، `103` سایر، `104` جیب به جیب، `105` اضافه به پس‌انداز  
هزینه: `201` قرض دادن، `202` سایر، `203` شارژ تلفن همراه، `204` قبوض، `205` کمک به خیریه، `206` جیب به جیب، `207` برداشت از پس‌انداز، `208` پس دادن، `209` قسط

## نکته‌ها
* انتقال‌ها دو ردیف جدا هستند (یکی منفی از مبدأ، یکی مثبت در مقصد). مبلغ دو سمت **همیشه برابر نیست** (مثلاً کارمزد)؛ ابزار اختلاف را جدا ثبت می‌کند.
* تراکنش‌هایی که دسته‌شان بعداً حذف شده یا از پیامک بدون دسته آمده‌اند `AccountId` نامعتبر دارند؛ ابزار آن‌ها را «نامشخص» می‌نامد.
* همه‌ی شناسه‌ها GUID متنی‌اند (`acc+AccTransaction+...`).
